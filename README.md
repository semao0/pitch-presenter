# Pitch Presenter

Режим докладчика для PDF и PPTX: текущий и следующий слайд, текст спикера, общий таймер и лимит на
каждый слайд. Отдельное окно с одними слайдами выводится на проектор или шарится в созвон, окна
синхронизируются между собой.

## Возможности

- PDF напрямую, PPTX/PPT/ODP/Key — через LibreOffice
- текст спикера в TOML, перечитывается на лету: правишь файл — текст обновляется; ошибка в файле
  не стирает текст с экрана, а показывается баннером с номером строки
- таймер выступления, лимит на слайд и темп «запас / отстаём»; без лимита время делится по числу слов
- метка «резерв» для слайдов, которые можно пропустить
- форматирование: **жирный**, *курсив*, ==подсветка==, `код`, списки, ремарки для себя
- окно показа само открывается на втором мониторе во весь экран
- сетка всех слайдов, переход по номеру, чёрный экран, размер шрифта, ширина колонок
- перетаскивание файлов в окно, недавние презентации, открытие файлов из системы

## Установка

Готовые сборки — в [Releases](https://github.com/semao0/pitch-presenter/releases):

- **macOS** — `.dmg` для Apple Silicon (`aarch64`) и Intel (`x64`). Приложение не нотаризовано:
  при первом запуске — правый клик → «Открыть».
- **Windows** — установщик `.exe` (или `.msi`); WebView2 скачается сам, если его нет.
- **Linux** — x64 и ARM64: `.deb` для Debian/Ubuntu, `.rpm` для Fedora или переносимый `.AppImage`.

Для PPTX/ODP/Key нужен [LibreOffice](https://www.libreoffice.org/); PDF открывается без него.

## Текст спикера

Файл `.toml` рядом с презентацией (`talk.pdf` → `talk.toml`) подхватывается сам. Один блок
`[[slide]]` на слайд, полный пример — [example.toml](example.toml):

```toml
title = "Объектив"    # необязательно: название в шапке
minutes = 8           # необязательно: длительность, иначе — из окна запуска

[[slide]]
n = 1                 # номер слайда — обязательно
title = "Боль"
time = "0:30"         # лимит: 30, "30s" или "0:30"
reserve = true        # метка «резерв»
text = '''
Происходит ли сейчас на площадке то, что должно быть по плану?

> пауза — ремарка для себя, в хронометраж не входит
'''
```

Формат строгий: опечатка в имени поля — ошибка с номером строки, а не молча потерянный лимит.

## Клавиши

| Клавиша | Действие |
|---|---|
| `→` `Space` `Enter` `PageDown`, клик по слайду | следующий слайд |
| `←` `Backspace` `PageUp`, правый клик | предыдущий слайд |
| цифры + `Enter` | перейти к слайду |
| `Home` / `End` | первый / последний слайд |
| `G` | все слайды |
| `B` или `.` | чёрный экран |
| `↑` `↓` | прокрутка текста |
| `+` / `-` | размер шрифта |
| `T` / `Shift R` | таймер: старт-пауза / сброс |
| `A` | открыть окно показа |
| `F` | полный экран |
| `?` или `F1` | справка |

Клавиши работают и когда в фокусе окно показа — оно пересылает их докладчику.

## Разработка

Нужны Rust, Node.js 22+ и pnpm; на Linux — `libwebkit2gtk-4.1-dev`
([подробнее](https://tauri.app/start/prerequisites/)).

```bash
pnpm install
scripts/fetch-pdfium.sh   # PDFium для текущей платформы → src-tauri/pdfium/
pnpm tauri dev            # запуск с hot reload
pnpm tauri build          # установщики → src-tauri/target/release/bundle/
```

Проверки (их же гоняет CI):

```bash
pnpm check && pnpm test                                   # фронтенд: типы, unit-тесты
cd src-tauri && cargo fmt --check && cargo clippy --all-targets && cargo test
```

Релиз: поднять версию в `package.json`, `src-tauri/Cargo.toml` и `src-tauri/tauri.conf.json`,
затем `git tag v2.0.0 && git push --tags` — GitHub Actions соберёт установщики для macOS
(Apple Silicon и Intel), Windows и Linux (x64 и ARM64) и положит их в черновик релиза.

### Устройство

[Tauri 2](https://tauri.app): бэкенд на Rust, интерфейс — Svelte 5 + TypeScript.

```
src-tauri/src/
  render.rs        PDF → PNG через PDFium, PPTX → PDF через LibreOffice; кэш по хэшу файла
  notes/           формат TOML и разметка текста (дерево, не HTML)
  session.rs       открытая презентация: слайд, чёрный экран, перечитывание заметок
  windows.rs       окно показа и выбор монитора
  commands.rs      API для фронтенда (invoke)
src/
  views/           экран запуска, окно докладчика, окно показа
  components/      сетка слайдов, справка, текст заметки, поле выбора файла
  lib/             API бэкенда, план выступления, таймер, предзагрузка слайдов
```

Состоянием показа (слайд, чёрный экран) владеет бэкенд и рассылает его событием в оба окна, так что
они не расходятся. Докладчик листает оптимистично — сразу, не дожидаясь ответа. Слайды
отдаются по протоколу `slide://` с id колоды в адресе, соседние держатся декодированными —
переключение мгновенное.
